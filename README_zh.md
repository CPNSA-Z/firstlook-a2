# FirstLook：阿尔茨海默病评估的"医生先判断"审阅界面（AD 与非 AD）

IIS 作业 2 原型 · Yaowen Zhang（3120714）· 37809/37792 Intelligent Interactive Systems

英文版（正式版本）：[README.md](README.md)。本文件是中文对照译本，如有出入以英文版为准。

> 研究原型，不用于临床。训练好的模型区分阿尔茨海默病（AD）与非 AD 参与者（认知正常、主观认知下降、MCI），不是 MCI 转 AD 的预测模型（见第 14 条）。应用只连接**推理服务**运行：真实的 ADNI 队列和五个训练好的折模型，由本地 GPU 电脑上的 `inference_server/` 提供；本仓库不含任何 ADNI 数据。没有离线或演示模式（见第 17 条）。

## 技术栈

- **Python 3.11+、Streamlit**：界面和会话状态（单文件 `app.py`）。
- **本地 LLM**，通过任意 OpenAI 兼容服务器接入（我用的是 LM Studio 加千问模型；换成私有模型也一样）：撰写结构化解释、回答助手的问题。全部在本地，患者数据不出网络。
- **FastAPI + PyTorch**（`inference_server/`，在 GPU 电脑上）：患者表、MRI 渲染、五个折模型、精确 SHAP 和 Grad-CAM。
- **openai** Python 客户端：连接 LM Studio，请求 `json_schema` 结构化输出。
- **Altair / pandas**：折分数点图和归因条形图。
- 查找页背景：MNI ICBM152 2009a 模板（© 1993–2009 Louis Collins, McConnell Brain Imaging Centre, MNI, McGill University；Fonov et al., 2011）。
- **pytest**（+ Streamlit `AppTest`）：测试规则、校验器，以及第 1 步不泄露模型输出这一性质。应用级测试使用推理服务的替身（`tests/fake_backend.py`，虚构患者），它不属于应用本身。
- 模型（为本项目训练；权重不在本仓库）：3D-CBAM CNN，用 FiLM 融合 7 个临床特征，在 990 名 ADNI 参与者上做五折交叉验证训练（脚本在 `model_training/`）。保存的各折检查点报告的最佳验证 AUC 为 0.897、0.872、0.956、0.773、0.913（均值约 0.88）。

## 运行或查看本项目

```bash
git clone https://github.com/CPNSA-Z/firstlook-a2.git && cd firstlook-a2
pip install -r requirements.txt
pytest -q                      # 测试（其中几项在无界面模式下针对替身服务运行应用）
```

运行方法：在 GPU 电脑上启动 `inference_server/`（见其 README），在 LM Studio 中加载模型，然后在运行应用的电脑上执行

```bash
export FIRSTLOOK_SERVER_URL="http://<gpu-pc-ip>:8008"  FIRSTLOOK_SERVER_TOKEN="<secret>"
export FIRSTLOOK_LLM_BASE_URL="http://<gpu-pc-ip>:1234/v1"  FIRSTLOOK_LLM_MODEL="<model id>"  FIRSTLOOK_LLM_API_KEY="<LM Studio token>"
streamlit run app.py
```

如果服务没有响应，应用会提示并停止运行，没有后备数据。截图时可设置 `FIRSTLOOK_PSEUDONYMS="CASE-001=<image id>,..."`，界面就会显示并接受化名而不是影像编号。请在 LM Studio 中关闭该模型的思考功能（它的 API 会忽略 `enable_thinking`）；否则应用会用更大的 token 额度重试一次。其他 OpenAI 兼容接口也可以通过相同的变量接入。请通过 `FIRSTLOOK_LLM_API_KEY` 提供你自己的密钥；仓库中不保存任何密钥。

建议的操作顺序：在条件 B 下打开一位患者，先做一个与模型不同的判断，再做一个一致的判断；打开另一位患者，说明一个不确定来源后使用 *View AI analysis*；在判断前后各问一次助手；在条件 A 下重复一位患者。每次保存的决定都会追加到 `logs/session_<id>.jsonl`。

文件位置：`model_training/`（底层模型的训练和 SHAP 脚本，附说明）、`firstlook/scope.py`（第 1 步的输入检查、第 3 步的不确定性检查）、`firstlook/llm.py`（提示词、schema、校验器）、`firstlook/model_adapter.py`（折分数范围）、`firstlook/backend.py`（推理服务客户端）、`docs/`（系统图）、`scripts/figures/`（作图脚本）。

## 开发记录

1. **范围调整：急诊分诊 → 记忆门诊。** 作业 1 提出的是急诊科的 LLM 分诊。我改做 MCI 转化，并为此训练了一个真实模型，让它的 SHAP 输出和失败记录来驱动设计，而不是用虚构的模型。研究问题（不确定性优先 vs 先给结论 + 事后 SHAP）不变。
2. **把自己的训练流程当作失败案例的来源。** 重读 `train.py` 发现，无法读取的扫描会被静默替换成全零体数据。这成了陷阱病例 C4，也是唯一的*阻断*规则：即使五折结果一致也不给分数（只看分歧会漏掉它）。测试：`test_failed_mri_blocks_model_even_when_folds_agree`。
3. **用折间分歧表示不确定性，而不是单一概率。** 最好的一折 AUC 达到 0.956，但五折从 0.77 到 0.96 不等，只报最好的一折会夸大性能。显示全部五个折分数能让这种波动可见。分档使用 0.25 的分歧阈值和 0.35–0.65 的临界区间（我的选择）。
4. **先判断，后看模型。** 依据 Yildirim et al.（2026）和锚定效应（第 06 讲），第 2 步先锁定医生自己的判断，第 3 步才显示任何内容；之后改判需要填写理由。
5. **LLM 只承担非核心任务。** 依据 Deng et al.（2025）和第 08 讲（流畅不等于证据），LLM 只负责整理病历：schema 中没有风险或诊断字段，每条线索都要附原文引用，代码检查引用确实出现在所引字段中，"模型是否看到过这一项"由 `FIELD_REGISTRY` 决定而不是相信 LLM，并删除下结论的语言。被删除的条目仍然可见。两个缓存样例故意含有错误，方便离线查看校验器的行为。真实模型出过哪些错、做了哪些修改，见第 17 条。
6. **本地模型，后备方案带标注。** LM Studio 让患者文本留在本机，也不需要密钥。服务器没有响应时，应用显示缓存输出并说明这一点，而不是悄无声息地失败（第 04 讲反馈）。（缓存后来被删除，改为带标注的模板，见第 17 条。）
7. **标签修复。** SHAP 图隐藏了一半坐标轴标签；改为按行设定高度步长后修复（已在截图上确认）。
8. **临床外观和 MRI 面板。** 看了最初的截图后，我认为界面不像临床软件，而且条件 A 缺少我在 A1 综述中批评过的 MRI 热图。于是加入了患者信息栏、步骤指示条和 MRI 面板。图像在 C4 中最关键：条件 A 在一张空白扫描上画出归因图，而条件 B 在读取失败提醒旁显示空白体数据。
9. **特征名核对（第 14 条有进一步更正）。** 把我的 SHAP 导出与训练实际使用的队列文件（`df_cohort_final.pkl`）对照后发现，SHAP 脚本的特征名错位了一位，因此修正了 SHAP 标签。

10. **第 1 步泄露了模型输出（审阅时发现，已修复）。** 审阅故事板 1 时，我注意到第 1 步在医生判断锁定之前就显示了"The five models disagree (range 0.47–0.81)"，临界病例还会显示均值（"The average score (0.xx) is near the decision line"）。这破坏了防锚定设计：同一个函数同时产生基于病历和基于分数的提醒，而界面在第 1 步把它们全部显示出来。该面板的步骤条还显示着第 3 步，因为它是从后面的截图裁出来的。
    - *修改：* 规则拆成两个函数。`input_checks(record)` 只接收病历，显示在第 1 步；`model_checks(view)` 只接收折分数，显示在第 3 步的折分数点旁边。MRI 读取失败规则留在第 1 步（它描述的是输入，不是分数），并且在第 3 步仍然隐去分数。这只适用于条件 B；条件 A 保留其自信的结论，因此 C4 的对比不变。步骤条现在高亮屏幕上可见的步骤（先 1–2，再 3–4）。图 1 和全部三张故事板都用新截图重新生成。
    - *验证：* `test_input_checks_take_the_record_only` 检查函数签名。`test_step1_screen_identical_whatever_the_fold_scores` 对每个病例分别用真实折分数和随机分数运行真实应用，断言判断前的页面文字完全相同且不含任何分数。我把旧逻辑放回去确认测试能发现问题：六个病例全部失败。

11. **推理型模型让实时调用卡住。** 在 LM Studio 中使用 Qwen 3.6 时应用毫无输出：模型花了约 3,000 个推理 token（约 80 秒），客户端超时后重试，而且每次 Streamlit 重新运行都会发起新请求。*修改：* 关闭思考（`enable_thinking: false` 和 `/no_think`），限制 `max_tokens`，不自动重试，调用放在能跨重新运行保留的后台任务中。
12. **审阅后重新设计：医生先判断，使用真实数据。** 审阅原型后，我认为流程不符合医生的工作方式。*修改：* 只按**影像编号**查找患者（隐私）；第 1 步显示数据库中的基本信息和患者本人的 MRI 切片；模型在后台运行，但在医生选择 **Lower concern**、**Higher concern** 或 **View AI analysis** 之前不显示任何结果。第三个按钮取代了"Uncertain"：把疑虑表述为"让我看看分析"，可以避免医生在患者面前显得没把握；它在日志中记为"不确定"。如果医生与模型一致，只显示简短确认并折叠细节；如果不一致（或模型不确定），则以中性措辞展开完整分析，改变初判需要填写理由。分析包括留出折估计、五个折分数点、精确 SHAP 条形图、Grad-CAM 热图，以及只根据这些数字撰写的本地 LLM 解释（任意 OpenAI 兼容模型；我用的是千问）。浮动助手回答问题；判断前它只拿到病历，所以即使它不遵守指令也无法泄露结果。*验证：* `test_screen_before_judgement_identical_whatever_the_model_says`、`test_assistant_gets_no_model_result_before_judgement`，以及在 42 例队列扫描上针对推理服务的端到端浏览器运行。
13. **FiLM 公式核对。** 编写推理服务时，我在脚本中发现两种 FiLM 层写法：`img * gamma + beta`（`train.py`）和 `img * (1 + gamma) + beta`（`run_shap.py`、`interpret_image.py`）。在第 3 折自己的 40 名验证受试者上，前者 AUC 为 0.968（训练日志为 0.956），后者为 0.902。服务采用训练时的写法；较早的 SHAP 图来自不匹配的层（已记在 `model_training/NOTES.md`）。
14. **用 ADNI 导出表重建患者表；更正两个早先的说法。** 用 `idaSearch_10_06_2025.csv`（生成队列文件的那份导出表）和队列笔记本自己的规则（每位参与者取最早的非空值）构建数据库，可以精确复现每一项模型输入（990/990，连哪些值缺失都一致）。医生现在看到的是真实单位（性别 M/F、APOE 基因型如 ε3/ε4、GDS、NPI-Q 和体重），而不是编码。这次核对更正了两点：(a) 第七项模型输入是**抑郁量表（GDS）**，不是我最初以为的 NPI-Q，因此修正了 `FIELD_REGISTRY`、SHAP 标签和 C3 的描述（性别编码确认：1 = M）；(b) 标签对 ADNI **阿尔茨海默病组**的每位参与者为 1，对其他所有人（包括认知正常者）为 0，所以模型区分的是 AD 与非 AD，而不是预测 MCI 转 AD。研究分组本身不存储，因为它就是标签。
15. **查找页。** 试用应用后，我把患者查找从侧栏移出：首屏只显示影像编号框、可选的 T1 上传（.nii/.nii.gz，发送到推理服务并替代库存扫描）和查找按钮，背景取自公开的 MNI 模板。加载病历和 MRI 时显示脉冲扫描动画遮罩。研究设置留在侧栏；页面顶栏不再隐藏，因为隐藏它也会去掉重新展开侧栏的按钮。*测试：* 查找页只显示表单；未知编号停留在查找页；"New patient search"返回查找页。随后按生产工具的标准调整了界面措辞：屏幕上不出现数据集名称、"random ID"、"research prototype"或免责声明标签（研究性质在此处和报告中说明），也不显示折编号、规则来源等模型内部信息。
16. **按我自己的原则审阅重新设计的版本。** 对"医生先判断"版本的审阅提出了五个问题；我接受了大部分并做了修改：
    - *范围措辞：* 界面、提示词和演示文字现在都写作阿尔茨海默病评估（AD 与非 AD），与模型实际训练的任务一致。
    - *上传的扫描：* 没有任何一折见过上传的扫描，因此主估计改为五个模型的均值（五个模型显示为同等地位）；SHAP 在各折间取平均（因为 Shapley 值对输出是线性的，所以仍然精确），Grad-CAM 也取平均。说明文字注明四个折仍见过该患者的临床数值。
    - *让 LLM 回到结构化、可校验的任务：* 文字解释现在是 JSON（`summary`、`key_drivers`、`uncertainty_note`、`limitations`）。代码删除任何指向非输入项、方向错误或大小错误的驱动因素，以及任何含有模型输出中不存在的数字或含诊断/指令性语言的句子；被删除的条目列在解释下方。LLM 无法访问时，用模板根据数字生成同样的结构。助手在顶部说明其依据范围，并被要求不要为了讨好而附和医生。
    - *认知强制：* 保留"View AI analysis"（这个标签不会让医生显得没把握），但只有在医生说明主要不确定来源（影像、分数、病史、缺失数据）后才解锁；日志记录它被使用的次数，以便衡量绕过率。最终决定增加第三个选项 *Uncertain — refer for further work-up*，因此不强迫下结论。
    - *被假定的输入：* 阅读队列笔记本发现，缺失的 APOE 和性别不是被填补，而是被编码为 0（非携带者、女性）；第 1 步现在会对此以及中位数填补的分数发出提醒。
    - *未修改：* 我没有在仓库中加入真实模型输出的缓存，因为源自 ADNI 的逐人输出不应分发。
    *测试：* 校验器、后备方案、不确定性关卡、三选项决定、被假定输入的提醒。
    - *离线审阅（后来删除，见第 17 条）：* 演示病例带有存储的 LLM 解释，每次显示时重新校验。
17. **真实本地运行；删除离线模式。** 在 GPU 电脑上配合本地 LLM 跑完整个流程，带来了四处改动。
    - *LLM 明明在运行却显示"无法连接"：* LM Studio 对这个模型忽略 `enable_thinking: false`，于是全部 2,000 个 token 都用在了推理上，回答为空。应用现在能把这种情况与服务器无法连接区分开，会用更大的额度重试一次，绝不使用被截断的推理草稿，并新增 *Regenerate* 按钮。界面上也不再显示模型名称。
    - *校验既太严又太松：* 它删掉了用病历标签写出的正确驱动因素（"FAQ functional score (0-30, …)"）和"NPI-Q 没有影响结果"这句正确的话，却放过了"NPI-Q 用队列平均值填补"（NPI-Q 不是输入）和"模型看不到 MRI 扫描"（模型能看到，是 LLM 看不到）。现在在提供给 LLM 的事实中标注非输入字段，匹配输入的各种标签，并删除这两类错误说法。离 0.5 的距离现在直接提供给 LLM，而不是在它自己算出来后被拒绝。
    - *故事板：* 所有面板现在都是这次运行在 Chrome 中的截图（编号已化名，LLM 文字为真实输出）；这次运行中每句解释都通过了校验，而助手有一次把两项填补的输入说成"已记录"，这不在校验范围内（已在报告中注明）。这些截图显示 ADNI 扫描和逐人数值，因此截图和故事板不放进本仓库（ADNI 数据使用协议），只出现在报告中；早先的故事板也出于同样原因从仓库中删除。
    - *没有离线模式：* 删除了六个合成病例、存储的 LLM 输出和转诊记录整理器（ADNI 病历没有文字记录），因此屏幕上的一切都来自真实模型。没有推理服务时，应用现在会提示并停止。*测试* 在 `tests/` 中针对替身服务运行应用（`test_no_offline_mode_without_the_service`、`test_failed_mri_withholds_the_result_in_the_app`、`test_claims_that_the_model_cannot_see_the_scan_are_removed`）。
